Researchers search from what they have read

Researchers now ask agents such as Codex or Claude Code to find the papers they need. The paper an agent returns affects what a researcher builds on, what they cite, and whether they consider an idea new.

Benchmarks such as LitSearch, PaSa, and SAGE build each query from a target paper or a passage that cites it. Such a query reuses the paper's terms, states the whole request at once, and always has an answer. A researcher instead starts from the papers they have already read. They describe what they want in their own terms, which the paper they need may show only implicitly. Their requirements accumulate as they read. And what they look for may not exist yet, so the need is unmet.

Results

CompLit has a Standard setting close to existing benchmarks and one setting for each need: Implicit, Cumulative, and Unmet. The four strongest agents we tested score 74–87% on Standard and lower on each of the other three.

Agents accept near-misses

Each Unmet query starts from a query whose target paper agents already find. We add one requirement the target does not meet, so the target becomes a near-miss and the correct answer is that no paper qualifies. Below is one such query from physics. All four agents open the near-miss and note that it ranks molecules by the highest score rather than the lowest. Codex abstains; the other three return the paper.

Across all Unmet queries, each agent opens the near-miss within its first ten tool calls in over 90% of Unmet queries, yet names a paper as a match in 47–82% of them, usually the near-miss. A researcher who receives such an answer may take an open direction for one already explored.

Implicit and Cumulative

On Implicit, the target paper is retrieved, opened, and chosen less often than on Standard. Retrieval drops by 12–27 points and the final answer by 19–37, so more is lost after the paper is found. In one biology query, Claude's searches return the target paper ten times, and it does not open it.

On Cumulative, Codex picks a wrong paper in 41% of conversations, against 66–74% for the others. Claude often picks one but recovers from more of them than the other agents; in one electrical engineering conversation it commits to RadioDUN, opens the target paper at the last turn, and writes, "This resolves it — and it overturns my earlier RadioDUN pick, which was wrong for these mechanics." Kimi and DeepSeek rarely recover. Codex and Claude, 2 points apart on Implicit, end 11 points apart.

How CompLit is built

Survey authors compare the papers they cover on the distinctions that matter in their field. We turn those table cells into requirements, add claims read from each target's figures and its arXiv record, and write each query around a research intent. We checked every requirement and query by hand, and an automatic check removes any query that another paper among the top 100 retrieved candidates also satisfies. CompLit has 870 single-turn queries and 220 conversations from 193 surveys across all eight arXiv domains.

Unmet queries start from queries whose target three reference systems (Harness-1, DeepSeek-V4-Pro, and GLM-5.2) all find. The added requirement swaps a value in the survey's table or reverses a claim read from one of the target's figures. The source surveys are removed from the search corpus; open-web agents open one in 3.8% of runs, and those runs are not more accurate.

Outlook

Judging whether a paper meets a need, and noticing when none does, is something researchers learn over years of reading in a field. An agent that returns a near-miss without pointing out what it lacks leaves the researcher no chance to make that judgment. We see two directions for future work: a harness for literature search, guided by where each agent fails and which papers it finds hard, and a model of a field distilled from its surveys, so that an agent knows how to search the field and check a requirement before the search begins.

Use the data

Four configurations, one test split each. Every row has the query, its requirements with evidence, the target paper (the near-miss on Unmet), and the source survey. Return one paper title per query, or an empty title to abstain. On Cumulative, a gpt-5.4-mini user simulator at temperature 0 delivers fixed user turns. The evaluation code is in the repository.
